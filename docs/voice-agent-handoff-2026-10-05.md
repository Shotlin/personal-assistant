## 1. The goal (owner = Sayan, speaks Hindi / Bengali / English, mixed)
A personal assistant that **talks to him on a normal WhatsApp call** like an intelligent human: understands, summarises,
advises (salesperson / developer knowledge), corrects him when he is wrong, hangs the call up for him, then hands the
work to the existing **Deep Agent** (sani-core) and **calls him back** with a short spoken result.
The character is **Shubh** (voice `shubh`, male). He never says "Sani": Sani is the owner's software name.
Voice stack: Sarvam `saaras:v4` realtime (listen) -> `sarvam-105b-conversations` (talk) -> `bulbul:v3` (speak). No newer Sarvam models exist (checked the changelog).
Phone path: unofficial `baileys-caller` (vendored). Use the **spare WhatsApp number only** (ban risk).

- Silence handling: WhatsApp sends no audio while the user is silent, so `SteadyFeed` (src/sttFeed.mts) feeds Sarvam a steady 20 ms clock and only sends silence for 1.5 s after speech (saves STT cost, lets Sarvam detect end of sentence).

- TTS `TtsStream` (src/sarvamTts.mts): bulbul:v3 WebSocket at 24 kHz, own 24->16 kHz resampler (src/audioDsp.mts), small level lift + soft limiter, per-sentence `style()` (pace/temperature change on the same socket, verified). - Turn taking `TurnManager` (src/turns.mts): merges the owner's fragmented speech (waits 0.65-1.8 s depending on whether the sentence sounds finished), ignores "haan/hmm" while Shubh talks, interrupts only for >=2 real words, a stop word, or 0.9 s sustained speech.

Fillers/reactions come from the model. English words stay in English letters (Sarvam rule).
- Cost controls: replies ~1 sentence (cap 160 chars; recap 520; advice 360), text sent to Bulbul one piece at a time only when <1.8 s of speech is queued (an interruption does not pay for the unspoken rest), disk cache for fixed lines (src/phraseCache.mts), cost line printed after each call. Bulbul = Rs 30 / 10K chars.
- Recording (src/recorder.mts): after each call `var/last-call.wav` (both voices mixed), `last-call-stereo.wav` (you left, Shubh right), `last-call-you.wav`, `last-call-shubh.wav`, plus `last-call-in.wav` (his side on the real timeline, for offline replay). ## 5. Facts learned (save yourself the pain)
- Sarvam chat: `POST /v1/chat/completions`, header `api-subscription-key`; `reasoning_effort: null` for speed (thinking is slow: 27 s for a board update). `sarvam-105b-conversations` talks well but is weak at precise reasoning (merged two times once). Streaming works; usage arrives in the last chunk.
- Bulbul WS: config can be re-sent between flushes (pace verified: 0.8 -> 2.9 s, 1.2 -> 1.9 s for the same sentence); `pitch`/`loudness` are v2 only; streaming is capped at 24 kHz; a WhatsApp call carries 16 kHz mono (engine reports `sampleRate:16000`), so 48 kHz REST adds nothing here. Romanised Hindi/Bengali hurts quality: native script, English words in Latin letters. Numbers over 4 digits with commas.
- Sarvam STT final arrives ~0.2 s after speech end; the VAD needs silence to end an utterance (hence SteadyFeed).
- WhatsApp: no audio is sent while the user is silent; `call.end()` hangs up the phone call; the library's "ended" event is unreliable on the remote side (events 38/71 patched in; remote-hang-up path not verified live).
- Node: run `tsx --env-file=.env`; typecheck with `npx tsc --noEmit --target es2022 --module nodenext --moduleResolution nodenext --skipLibCheck --allowImportingTsExtensions src/*.mts examples/*.mts` (currently clean).
- A background `npm run talk` started by the assistant leaves a process running if the user stops it; check `ps` and never run two calls at once (they overwrite `var/last-call.log`).
